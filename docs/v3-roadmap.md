# v3.0.0 Roadmap（規劃定案）

> 狀態（2026-11-10）：規劃已定案，2.1.0 已發布，可以開始做。
> 主題：**時間** —— 記下每件事花了多少時間，並依時間回顧工作。

## 實作順序

每一步開一個 branch，做完一段合併一段（比照 2.0.0）。

| 步驟 | 內容 | 依賴 |
|---|---|---|
| 0 ✅ | 資料基礎：schema 8、備份格式 3、舊資料轉換、文件與 golden 資料 | — |
| 1 ✅ | 起始／結束時間（輸入、自動補、顯示、回報、PPT、AI 指示） | 0 |
| 2 | 搜尋紀錄 | —（任何時候都可以做） |
| 3 | 範圍報告合併延續鏈 | — |
| 4 | 工時統計 | 0、1、3 |
| 5 | 甘特圖 | 1、3 |
| 6 | 發布：CHANGELOG、README、版本號、打包 | 全部 |

## 必做

### 1. 紀錄的起始／結束時間（使用者提出）

**每筆紀錄一定有起始與結束時間。** 使用者可以自己填，沒填就自動補。

- 記錄視窗有「起始」「結束」兩個時間欄位，預設空白，讓使用者自己打
  - 原本的「時間」欄位不再顯示（`time` 改成內部的建立時間，見〈資料格式與相容〉）
  - 不做「現在結束」按鈕，也不做 −15 分之類的快速按鈕
- 規則：
  - 起始和結束必須一起填，或一起不填；只填一個不能存
  - 結束時間不能早於起始時間，否則不能存
  - 起訖必須在紀錄的同一天；跨午夜的工作不能存，錯誤訊息直接提示「請拆成兩筆」
  - 紀錄日期是今天時，結束時間最晚只能到存檔當下；填超過的話，自動改成存檔當下的時間
    （改了之後起始比結束晚，就照上面的規則不能存）
- **新增**紀錄時，起訖都沒填就自動補：
  - 日期是今天：
    - 起始＝「前一則」的結束時間，結束＝存檔當下
    - 「前一則」＝同一天、還沒刪除的紀錄中，不晚於存檔當下的最晚結束時間（不跨日找；用最晚的結束時間，而不是最後建立的，避免補記的舊事把起點拉回去；結束時間比現在晚的紀錄不算）
    - 沒有前一則：起始和結束都是存檔當下（時長 0）
  - 日期不是今天（補記別天的事）：不自動補，起訖必須自己填，沒填就不能存
- **編輯**舊紀錄時不自動補，起訖都必須有值，清空就不能存
- 「帶入未完成項目」「追加今日進度」產生的紀錄：起訖都是產生當下的時間（時長 0），不沿用前一筆的時間，之後讓使用者自己改
- 顯示：
  - 主視窗清單：`09:00–10:30（1 小時 30 分）`
  - report.md 每一行：`[09:00–10:30 1.5h]`（時段與時長都寫）
  - PPT 每頁顯示時段
  - 時長 0 的紀錄只顯示一個時間：清單與回報寫 `09:12`，不寫 `09:12–09:12（0 分）`
- 不做右鍵「結束這項工作」（每筆都一定有結束時間，用不到）
- 主視窗清單的排列方式不變（依優先順序、再依標題）

### 2. 工時統計

- 左邊分類樹多一欄「時數」，算這一天（含子分類）紀錄的總時長
  - 比照「顯示進度」，加一個「顯示時數」勾選框
- 範圍整理（週報、月報）加「## 工時統計」：依分類樹列出每個分類的時數與百分比
- 時段重疊的紀錄照樣各自計算，不自動扣除；統計旁邊註明這一點
- 時長 0 的紀錄算 0
- 一條延續鏈中途改過分類時，每筆的時數算在那筆自己的分類（分類加總才對得起來）；整條鏈的總時數只顯示在那件工作本身

### 3. 搜尋紀錄

- 主視窗加搜尋框，不限日期，找標題、內容、tag、分類
- 結果依日期排列（新的在前），雙擊跳到那一天並選取那筆

### 4. 範圍報告合併延續鏈

- 範圍整理（週報、月報）時，同一件工作（同一條延續鏈：帶入或追加進度串起來的紀錄）只列一次
- 這件工作底下依日期列出各天的進展（狀態、內容），最後的狀態以最新那筆為準
- 延續鏈可能分岔（同一筆被帶入成兩筆）：整棵樹當成一件工作；如果分岔後各有最新的一筆，兩個最新狀態都列出
- 分組用範圍內最新那筆的分類
- 延續鏈的開頭早於報告範圍：只列範圍內的進展，加註「（延續自 MM-DD）」，時數也只算範圍內的
- 加上工時統計後，這件工作的時數是整條鏈（範圍內）加總
- 單日的工作回顧不變

### 5. 甘特圖（使用者提出）

- 主視窗加「📈 甘特圖」按鈕，選日期範圍（和範圍整理一樣，有本週／上週／本月／上個月）
- 只選一天：橫軸是時間，每筆紀錄畫成一條；時長 0 的畫成一個點
- 選好幾天：橫軸是日期，每件工作（一條延續鏈，分組規則同第 4 項）一列，有做的那幾天畫成色塊
- 依分類樹分組排列；顏色用狀態的顏色；滑鼠移上去顯示標題與時段，雙擊跳到那筆紀錄
- 可以存成 PNG
- 用 Qt 自己畫（QPainter），不加新套件

## 3.x 再說（不放進 3.0.0）

| 功能 | 說明 |
|---|---|
| 截止日期 | 紀錄可以設截止日；帶入未完成項目時逾期的標成紅色，回報標「（截止 MM-DD）」。要再改一次資料格式 |
| 日曆瀏覽 | 主視窗日期旁邊可以開一個月曆，有紀錄的日子加點，點了就跳過去 |
| 紀錄範本 | 常用的開頭（例如「站會」「Code review」）一鍵帶入標題、分類、tag |

不做：計時器（起訖時間由使用者自己填，或依規則自動補）。

## 資料格式與相容

- SCHEMA_VERSION 7 → 8：
  - `entries` 新增 `start_time TEXT NOT NULL`、`end_time TEXT NOT NULL`（格式 `HH:MM`，同一天，`start_time <= end_time`）
  - 原本的 `time` 保留，意義改成「建立時間」，只在內部用來排序，介面上不再顯示
  - 舊資料轉換（轉換前自動備份資料庫），依新增紀錄的規則回推：
    - `end_time` ＝ 原本的 `time`
    - `start_time` ＝ 同一天前一筆（依原本的 `time` 排序）的 `end_time`；每天第一筆的 `start_time` ＝ 自己的 `time`（時長 0）
    - 回推出來的時長只是估計，CHANGELOG 要說明
- 備份 bundle 的 FORMAT_VERSION 2 → 3：
  - 紀錄多 `start_time`、`end_time` 兩個欄位
  - 讀舊的 1、2 版 bundle 時沒有這兩個欄位，用和資料庫轉換相同的規則回推
  - 2.x 的程式讀到 3 版 bundle 會拒絕（`sync.py` 的 `SUPPORTED_VERSIONS` 已經會擋，補一個測試固定下來）
- 要更新的地方：
  - `docs/data-format.md`
  - `tests/golden/` 加一組有時段的資料
  - `instructions.md` 預設內容加一行說明時段與工時統計（用 `OLD_LINES` 自動升級）

## 已決定的事（2026-11-10 討論）

| 問題 | 決定 |
|---|---|
| 回報要寫時長還是時段 | 都寫 |
| 「結束這項工作」 | 不做（每筆都一定有起訖） |
| 候選功能 | 3.0 都不做；計時器不做，其他放 3.x |
| 起始時間預設 | 欄位預設空白；新增時沒填就依「前一則」規則自動補 |
| 只填起始 | 不行，起訖必須一起填 |
| 帶入／追加產生的紀錄 | 起訖都是產生當下（時長 0），不沿用前一筆 |
| 延續鏈分岔 | 整棵樹當一件工作，各分岔的最新狀態都列 |
| 中途改分類 | 分組用範圍內最新那筆；時數算在各筆自己的分類 |
| 鏈的開頭早於範圍 | 只列範圍內，加註延續自，時數只算範圍內 |
| 跨午夜 | 不能存，提示拆成兩筆 |
| 結束時間晚於現在 | 自動改成存檔當下 |
| 補記別天的事 | 不自動補，起訖必填 |
| 編輯時清空起訖 | 不能存 |
| 舊資料 | 依規則回推起訖 |
| 時長 0 | 只顯示一個時間；統計算 0；甘特圖畫成點 |
| 分類樹時數欄 | 加「顯示時數」勾選框 |
| 清單排列 | 不變 |
